## 3. `controlador.ps1` — interface FIXA

### 3.1 Parâmetros

```powershell
param(
  [Parameter(Mandatory)][string]$RepoPath,     # pasta do repositório git onde o executor trabalha
  [Parameter(Mandatory)][string]$TarefasPath,  # caminho do TAREFAS.json (FORA do repositório)
  [Parameter(Mandatory)][string]$EstadoDir,    # pasta de estado/log/notificações (FORA do repositório)
  [Parameter(Mandatory)][string]$TestCmd,      # comando de teste; código de saída 0 = passou
  [Parameter(Mandatory)][string[]]$TestPaths,  # padrões dos arquivos de teste (seção 3.4)
  [int]$TimeoutSec     = 900,                  # tempo máximo por chamada ao executor
  [int]$MaxTentativas  = 3,                    # tentativas por tarefa
  [double]$MaxCustoUsd = 10,                   # teto de custo acumulado da execução
  [double]$MaxMinutos  = 240,                  # teto de tempo total da execução (aceita fração: 0.05 = 3 s)
  [string]$ClaudeCmd   = 'claude'              # executável do executor (o teste troca por um simulado)
)
```

`TarefasPath` e `EstadoDir` ficam fora do repositório porque o rollback (`git reset --hard` + `git clean -fd`) apagaria ou reverteria o estado do controlador.

### 3.2 Como chamar o executor

- Iniciar `$ClaudeCmd` como **processo externo** (deve funcionar com `.exe` e com `.cmd`), com diretório de trabalho = `$RepoPath`.
- Argumentos obrigatórios: `-p`, `--output-format json`, `--permission-mode dontAsk`.
- O prompt enviado deve conter **o texto integral do campo `prompt` da tarefa** (pode haver texto adicional). Ele pode ir como argumento depois de `-p` **ou pela entrada padrão (stdin)**. Prompts com várias linhas devem ir por stdin: no Windows, um executável `.cmd` corta quebras de linha nos argumentos.
- Proibido: `--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions` e `--permission-mode` com qualquer valor que não seja `dontAsk`.
- Ler o JSON da saída padrão. Campos usados: `is_error`, `result`, `total_cost_usd`.
- **Falha do executor** (conta como tentativa falhada, com rollback): código de saída diferente de 0, `is_error: true`, saída que não é JSON, ou timeout. Custo: soma-se `total_cost_usd` quando houver; sem JSON válido, soma-se 0 e registra-se no log.

### 3.3 Ciclo de cada tarefa

1. Escolher a próxima tarefa `pending` cujas dependências (`depends_on`) estejam todas `done`, na ordem do arquivo.
2. Registrar o commit base (`git rev-parse HEAD`) em `estado.json` (`commit_base`) e o SHA-256 dos arquivos de teste.
3. **Incrementar `tentativas` e gravar `TAREFAS.json` ANTES de chamar o executor** (status `in_progress`).
4. Chamar o executor. Timeout = encerramento REAL do processo **e de todos os filhos**.
5. Se o executor falhou (3.2): primeiro verificar os gatilhos do passo 7 (se algum ocorreu, vale o `hold`, sem rollback); senão, rollback e nova tentativa.
6. Senão, o **próprio controlador** roda o teste: `pwsh -NoProfile -Command $TestCmd`, com diretório de trabalho = `$RepoPath`. Não confiar no relato do executor.
7. Gatilhos críticos (R1), verificados contra o commit base. **Eles têm precedência sobre o resultado do teste**: se algum ocorrer, vale o `hold`, mesmo que o teste tenha passado ou falhado:
   - qualquer arquivo de teste alterado, criado ou removido;
   - migrations (caminho contendo `migration`);
   - `package.json`, `package-lock.json`, `requirements.txt`, `pyproject.toml`;
   - exclusão de arquivo rastreado que existia no commit base.
   - Se algum ocorrer: status `hold`, **sem commit e sem rollback** (preservar a evidência), notificar e **encerrar a execução** (nenhuma outra tarefa é iniciada).
8. Teste passou: commit com a mensagem exata `tarefa <id>: <titulo>` (sensível a maiúsculas), status `done`.
9. Teste falhou: `git reset --hard <commit_base>` + `git clean -fd`, SOMENTE dentro de `$RepoPath`; nova tentativa. Ao atingir `$MaxTentativas`: status `failed`. Dependentes ficam `pending`; independentes continuam.
10. Após cada chamada, atualizar o custo acumulado. Se ele passar de `$MaxCustoUsd`, ou o tempo total passar de `$MaxMinutos`: **concluir a tarefa atual pelo fluxo normal (passos 6–9)**, notificar e pausar (encerrar sem iniciar outra chamada).

O controlador só escreve no repositório por meio de `git add`, `git commit`, `git reset` e `git clean`. Arquivos não rastreados dentro de `.claude/` (ex.: `settings.local.json`) são permitidos e não contam como sujeira.

### 3.4 `$TestPaths`

- Cada padrão é relativo à raiz do repositório, com `/` como separador, comparado com o operador `-like` do PowerShell (sem distinção de maiúsculas). O `*` atravessa pastas (`testes/*` casa `testes/a.ps1` e `testes/sub/b.ps1`).
- Valem os arquivos rastreados e os não rastreados que casarem com algum padrão.
- Como `pwsh -File` entrega um único texto para parâmetros `[string[]]`, o controlador deve aceitar também vários padrões num único texto separado por vírgula (`testes/*,spec/*`).

### 3.5 Arquivos em `$EstadoDir`

| Arquivo | Formato |
|---|---|
| `estado.json` | No mínimo: `tarefa_atual` (string ou null), `tentativa` (int), `commit_base` (hash), `custo_acumulado_usd` (número), `inicio` (ISO 8601), `atualizado_em` (ISO 8601), `status_execucao` (`rodando` \| `concluido` \| `hold` \| `pausado` \| `falhou`). Regravado a cada etapa (heartbeat). |
| `log.jsonl` | Uma linha JSON por evento, cada uma com `ts` e `evento`. |
| `notificacoes.txt` | Escrito pela função `Notificar()`, isolada. Por ora só grava texto aqui. |

### 3.6 Retomada

Rodar de novo com os mesmos parâmetros retoma de onde parou: tarefas `done` são puladas; tarefa `in_progress` volta ao `commit_base` registrado (reset + clean) e recomeça, **mantendo a contagem de tentativas e o custo acumulado**. O teto `$MaxMinutos` conta a partir do início de cada execução e não se acumula entre retomadas; o teto de custo, sim.

### 3.7 Códigos de saída (ordem de prioridade)

| Prioridade | Código | Situação |
|---|---|---|
| 1 | 2 | Encerrou por `hold` |
| 2 | 3 | Pausou por teto de custo ou de tempo |
| 3 | 1 | Terminou com ao menos uma tarefa `failed` |
| 4 | 0 | Todas as tarefas `done` |

## 4. `TAREFAS.json`

```json
{
  "tarefas": [
    { "id": "T1", "titulo": "...", "prompt": "...", "depends_on": [], "status": "pending", "tentativas": 0, "critica": false }
  ]
}
```

Status válidos: `pending`, `in_progress`, `done`, `failed`, `hold`. O controlador atualiza o próprio arquivo.

## 5. `.claude/settings.json`

- `permissions.defaultMode`: `"dontAsk"`.
- `allow`: apenas git (`status`, `diff`, `add`, `commit`, `log`), o comando de teste, leitura e edição dentro do repositório. A forma `Bash(x *)` e a forma `Bash(x:*)` são equivalentes.
- `deny`: remoção fora do repo, `Invoke-Expression`, `Start-Process`, `curl`/`Invoke-WebRequest`, `git push`, edição dos arquivos de teste.
- Cuidado obrigatório (ver `REFERENCIA_CLAUDE_CODE.md`, seção 3): em `claude -p`, regras `allow` do `.claude/settings.json` do projeto **não valem** se a pasta não for confiada. O kit precisa resolver isso. Como resolve é avaliado pelo júri.

> Na v0.1, o Kimi não encontrou três itens (`--permission-prompts`, `--bare` sem login da assinatura, SIGTERM/143). Foram reconferidos na página `headless.md` nas seções indicadas abaixo; o Perplexity também os confirmou.

## 1. Modo headless — [headless](https://code.claude.com/docs/en/headless.md)
- `claude -p "<prompt>"` roda sem interface. Sai com código 0 no sucesso e diferente de zero na falha; falhas dentro da execução aparecem como resultado na saída padrão. (seção "Basic usage")
- O modo não interativo lê a entrada padrão (stdin): `cat arquivo | claude -p "..."`. (seção "Pipe data through Claude")
- `--output-format json` devolve JSON com `result`, `session_id` e metadados, incluindo `total_cost_usd`, que é **estimativa do lado do cliente**. (mesma seção)
- Encerrado por SIGTERM, sai com código 143 e encerra a árvore de processos dos comandos Bash em andamento. (seção "Stop a run with SIGTERM")
- `--bare` pula hooks, skills, CLAUDE.md, plugins e `.mcp.json`, e **não usa o login da assinatura**: exige `ANTHROPIC_API_KEY` ou um `apiKeyHelper` passado em `--settings`. (seção "Start faster with bare mode")
- `--permission-prompts none` (v2.1.259+) avisa o Claude de que ninguém pode aprovar e para não insistir. (seção "Turn off permission prompts in unattended runs")

## 2. Modos de permissão — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- Modos: `default` (Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`.
- **`dontAsk`**: nega automaticamente tudo o que pediria aprovação. Roda só leituras na pasta de trabalho, comandos somente-leitura embutidos e o que estiver em `permissions.allow` ou `--allowedTools`. Não aparece no ciclo Shift+Tab; usa-se `--permission-mode dontAsk`.
- O modo inicial de `claude -p` depende de a sessão buscar *feature flags* (e da versão): pode ser `default` ou `auto`. **Por isso o kit deve passar o modo explicitamente.**
- `defaultMode` no `.claude/settings.json` do projeto vale para todos os modos, exceto `auto` e `bypassPermissions`.
- `--dangerously-skip-permissions` equivale a `bypassPermissions`; indicado só em container ou VM isolados.
- Escrita em caminhos protegidos (`.git`, `.claude`, `.vscode` etc.) é **negada** em `dontAsk`.

## 3. Ponto crítico: confiança da pasta em `claude -p` — [permissions](https://code.claude.com/docs/en/permissions.md)
- Regras `permissions.allow` do `.claude/settings.json` do projeto **não são aplicadas** em `claude -p` numa pasta nunca confiada; o Claude Code avisa no stderr. Regras `deny` e `ask` continuam valendo.
- Hooks do `.claude/settings.json` do projeto **rodam** em `claude -p` mesmo sem confiança. ([headless](https://code.claude.com/docs/en/headless.md), seção "Start faster with bare mode")
- Saídas documentadas: (a) passar as regras por `--settings <arquivo>` ou (b) `--allowedTools`; (c) marcar a pasta como confiada em `~/.claude.json` (`projects["<raiz>"].hasTrustDialogAccepted = true`); (d) colocar as regras num `.claude/settings.local.json` **não rastreado pelo git**, que em `-p` é aplicado após a checagem do git (seção "When your local settings file needs trust").

## 4. Sintaxe das regras — [permissions](https://code.claude.com/docs/en/permissions.md)
- Formato `Ferramenta(especificador)`. Precedência: **deny → ask → allow**; a primeira que casa decide.
- Bash: `Bash(npm run *)`; o espaço antes do `*` importa (`Bash(ls *)` não casa `lsof`). A forma `Bash(ls:*)` é equivalente a `Bash(ls *)`.
- PowerShell: mesma forma, `PowerShell(Get-ChildItem *)`; aliases são normalizados e a comparação ignora maiúsculas.
- Arquivos: `Edit(caminho)` e `Read(caminho)` no padrão gitignore. `/caminho` é relativo à origem do arquivo de settings; `//caminho` é absoluto. No Windows, caminhos viram forma POSIX (`C:\Users` → `/c/Users`). Regras `Write(...)` não são consultadas: use `Edit(...)`.
- **Regras de Bash/PowerShell não são barreira de segurança**: `Bash(rm *)` não pega `/bin/rm` nem `bash -c 'rm …'`. A proteção real é a verificação externa do controlador.

## 5. Windows — [tools-reference](https://code.claude.com/docs/en/tools-reference.md)
- Ferramenta PowerShell: ativada automaticamente sem Git Bash; com Git Bash, ligada por padrão em contas claude.ai e Console. `CLAUDE_CODE_USE_POWERSHELL_TOOL=0` desliga, `=1` liga. Texto da doc: "On Windows, set the variable to `0` to turn the tool off." (seção "Enable the PowerShell tool").
- **Sandbox não é suportado no Windows nativo** (seção "Preview limitations"; ver também [permission-modes](https://code.claude.com/docs/en/permission-modes.md)).
- **Ponto em disputa, não confirmado:** o Perplexity afirma que a página tools-reference tem uma seção "Bash deny rules also turn off the PowerShell tool", segundo a qual, no Windows com Git Bash, até um deny com escopo (ex.: `Bash(git push *)`) desliga a ferramenta PowerShell. Em 16/10/2026, a página entregue ao Claude não tinha essa seção (as seções da ferramenta PowerShell eram "Enable the PowerShell tool", "Shell selection…", "Windows encoding and exit codes" e "Preview limitations"). Consequência neutra para todos: os jurados **não** penalizam denies de shell escritos como `Bash(...)` nem como `PowerShell(...)`, e o piloto deve conferir com `/permissions` qual ferramenta de shell ficou ativa.
- `Remove-Item` em caminhos de sistema ou com curinga final é negado em qualquer modo. Texto da doc: "**System paths**: … Claude Code denies the command in every mode, without asking you." e "**Wildcards**: a bare `*`, or any target ending in `/*` or `\*` … Claude Code denies the command in every mode, without asking you". Com `-Recurse` na pasta de trabalho ou numa pasta acima dela, é negado em `dontAsk`. ([permission-modes](https://code.claude.com/docs/en/permission-modes.md), seção "Remove-Item in PowerShell")

- Um `.cmd` corta quebras de linha nos argumentos: prompts com várias linhas devem ir por stdin.

# Verifica só as FLAGS (A3/M1): o texto do prompt pode conter qualquer palavra.
function Args-Validos([string]$mockDir) {
  $arquivos = Get-ChildItem $mockDir -Filter 'args-*.json' -ErrorAction SilentlyContinue
  if (-not $arquivos) { return $false }
  foreach ($a in $arquivos) {
    $l = @((Get-Content $a.FullName -Raw | ConvertFrom-Json).args)
    if (($l -contains '--dangerously-skip-permissions') -or ($l -contains '--allow-dangerously-skip-permissions')) { return $false }
    if (-not (($l -contains '-p') -or ($l -contains '--print'))) { return $false }
    $okOut = $l -contains '--output-format=json'
    $okPm  = $l -contains '--permission-mode=dontAsk'
    for ($i = 0; $i -lt $l.Count - 1; $i++) {
      if ($l[$i] -eq '--output-format') { $okOut = $okOut -or ($l[$i + 1] -eq 'json') }
      if ($l[$i] -eq '--permission-mode') { if ($l[$i + 1] -ne 'dontAsk') { return $false } else { $okPm = $true } }
    }
    if (@($l | Where-Object { $_ -like '--permission-mode=*' -and $_ -ne '--permission-mode=dontAsk' }).Count) { return $false }
    if (-not ($okOut -and $okPm)) { return $false }
  }
  if (Get-ChildItem $mockDir -Filter 'cwd-errado-*.txt' -ErrorAction SilentlyContinue) { return $false }
  return $true
}

function Guardar-Saidas($exec, [string]$base, [string]$sufixo) {

  $exec.Out.Wait(5000) | Out-Null; $exec.Err.Wait(5000) | Out-Null

}

function Novo-Lancador([string]$base, [string]$plano, [string]$mockDir) {
  # Lançador do simulado, fora do repositório, com as variáveis MOCK_* definidas só para o processo do simulado.
  $dir = Join-Path $base 'executor'
  New-Item -ItemType Directory -Force -Path $dir | Out-Null
  if ($IsWindows) {
    $arq = Join-Path $dir 'claude.cmd'
    Set-Content -Encoding ascii $arq @(
      '@echo off',
      "set `"MOCK_PLANO=$plano`"",
      "set `"MOCK_DIR=$mockDir`"",
      "pwsh -NoProfile -ExecutionPolicy Bypass -File `"$FakeClaudePs1`" %*",
      'exit /b %ERRORLEVEL%')
  } else {
    $arq = Join-Path $dir 'claude.sh'
    Set-Content $arq @(
      '#!/usr/bin/env bash',
      "export MOCK_PLANO='$plano'",
      "export MOCK_DIR='$mockDir'",
      "pwsh -NoProfile -File '$FakeClaudePs1' `"`$@`"",
      'exit $?')
    chmod +x $arq
  }
  return $arq
}

function Rodar-Cenario([string]$nome, [hashtable]$cfg) {
  # Pasta de trabalho com nome aleatório, na pasta temporária do sistema: nenhum caminho passado ao
  # controlador revela o cenário, e não há pastas de cenários anteriores ao lado. Ao final, a pasta é
  # copiada para <SaidaDir>/work/<cenário> (para os artefatos) e apagada.
  $base = Join-Path ([System.IO.Path]::GetTempPath()) ('kit-' + [guid]::NewGuid().ToString('N').Substring(0, 12))
  New-Item -ItemType Directory -Force -Path $base | Out-Null
  $repo = Novo-Repo $base
  $baseCommit = (GitR $repo rev-parse HEAD)
  if (-not $baseCommit) { throw "Falha ao criar o repositório de teste do cenário $nome (commit base vazio)" }
  $c = @{ Base = $base; Repo = $repo; BaseCommit = $baseCommit; Cfg = $cfg
          Estado = (Join-Path $base 'estado'); Mock = (Join-Path $base 'mock'); Tarefas = (Join-Path $base 'TAREFAS.json')
          Sentinela = (Join-Path $base 'sentinela-fora-do-repo.txt') }
  New-Item -ItemType Directory -Force -Path $c.Estado | Out-Null
  Set-Content $c.Sentinela 'este arquivo fica fora do repo e não pode ser apagado'
  @{ tarefas = $cfg.Tarefas } | ConvertTo-Json -Depth 5 | Set-Content $c.Tarefas
  $planoPath = Join-Path $base 'plano.json'
  $cfg.Plano | ConvertTo-Json -Depth 5 | Set-Content $planoPath
  $c.Nome = $nome
  $c.ClaudeCmd = Novo-Lancador $base $planoPath $c.Mock

  if ($cfg.Interromper) {
    # C6: primeira execução é interrompida (árvore inteira) enquanto o executor está travado.
    $e1 = Iniciar-Controlador $c
    $limite = (Get-Date).AddSeconds(45)
    while (-not (Test-Path (Join-Path $c.Mock 'pid-mock.txt')) -and (Get-Date) -lt $limite -and -not $e1.Proc.HasExited) { Start-Sleep -Milliseconds 500 }
    Start-Sleep -Seconds 1
    if (-not $e1.Proc.HasExited) { $e1.Proc.Kill($true); $e1.Proc.WaitForExit(10000) | Out-Null }
    Matar (Join-Path $c.Mock 'pid-filho.txt'); Matar (Join-Path $c.Mock 'pid-mock.txt')
    Guardar-Saidas $e1 $base '-1'
    Remove-Item (Join-Path $c.Mock 'pid-mock.txt'), (Join-Path $c.Mock 'pid-filho.txt') -ErrorAction SilentlyContinue
  }

  $sw = [System.Diagnostics.Stopwatch]::StartNew()
  $e = Iniciar-Controlador $c
  $terminou = $e.Proc.WaitForExit($LimiteHarnessSec * 1000)
  if (-not $terminou) { $e.Proc.Kill($true); $e.Proc.WaitForExit(10000) | Out-Null }
  $sw.Stop()
  Guardar-Saidas $e $base ''
  $c.Exit = if ($terminou) { $e.Proc.ExitCode } else { 'estourou-limite-do-harness' }
  $c.Segundos = [math]::Round($sw.Elapsed.TotalSeconds, 1)
  Start-Sleep -Seconds 2

  $nucleo = [ordered]@{}; $aux = [ordered]@{}
  foreach ($k in $cfg.Nucleo.Keys) { try { $nucleo[$k] = [bool](& $cfg.Nucleo[$k] $c) } catch { $nucleo[$k] = $false } }
  foreach ($k in $cfg.Aux.Keys)    { try { $aux[$k]    = [bool](& $cfg.Aux[$k] $c) }    catch { $aux[$k] = $false } }
  Matar (Join-Path $c.Mock 'pid-filho.txt'); Matar (Join-Path $c.Mock 'pid-mock.txt')
  $okN = -not ($nucleo.Values -contains $false)
  $okA = -not ($aux.Values -contains $false)
  $pts = $(if ($okN) { 4 } else { 0 }) + $(if ($okN -and $okA) { 1 } else { 0 })
  $nChamadas = Chamadas $c.Mock
  $destino = Join-Path $SaidaDir "work/$nome"
  if (Test-Path $destino) { Remove-Item -Recurse -Force $destino }
  New-Item -ItemType Directory -Force -Path (Split-Path $destino) | Out-Null
  Copy-Item -Recurse -Force $base $destino -ErrorAction SilentlyContinue
  Remove-Item -Recurse -Force $base -ErrorAction SilentlyContinue
  [ordered]@{ cenario = $nome; pontos = $pts; nucleo_ok = $okN; auxiliar_ok = $okA
    exit_code = $c.Exit; segundos = $c.Segundos; chamadas_ao_executor = $nChamadas
    nucleo = $nucleo; auxiliar = $aux }
}

function Commits-Exatos($c, [string[]]$ids) {
  # Exatamente estes commits desde a base, na ordem dada (mais antigo primeiro), com a mensagem exata.
  $s = @(GitR $c.Repo log --reverse --format=%s "$($c.BaseCommit)..HEAD")
  if ($s.Count -ne $ids.Count) { return $false }
  for ($i = 0; $i -lt $ids.Count; $i++) { if ($s[$i] -cne "tarefa $($ids[$i]): Corrigir Soma ($($ids[$i]))") { return $false } }
  return $true
}
function Um-Commit($c, [string]$id) {
  ((GitR $c.Repo rev-list --count "$($c.BaseCommit)..HEAD") -eq '1') -and
  ((GitR $c.Repo log -1 --format=%s) -ceq "tarefa ${id}: Corrigir Soma ($id)")
}

function Chamar($id) {

  $psi.WorkingDirectory = $RepoPath; $psi.RedirectStandardOutput = $true; $psi.RedirectStandardInput = $true; $psi.UseShellExecute = $false
