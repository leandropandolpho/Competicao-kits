## 3. `controlador.ps1` — interface FIXA

A interface abaixo é obrigatória. É o que permite aos testes objetivos rodarem igualmente para todos os kits.

### 3.1 Parâmetros

```powershell
param(
  [Parameter(Mandatory)][string]$RepoPath,     # pasta do repositório git onde o executor trabalha
  [Parameter(Mandatory)][string]$TarefasPath,  # caminho do TAREFAS.json (FORA do repositório)
  [Parameter(Mandatory)][string]$EstadoDir,    # pasta de estado/log/notificações (FORA do repositório)
  [Parameter(Mandatory)][string]$TestCmd,      # comando de teste; exit code 0 = passou
  [Parameter(Mandatory)][string[]]$TestPaths,  # caminhos/globs relativos ao repo dos arquivos de teste
  [int]$TimeoutSec    = 900,                   # tempo máximo por chamada ao executor
  [int]$MaxTentativas = 3,                     # tentativas por tarefa
  [double]$MaxCustoUsd = 10,                   # teto de custo acumulado da execução
  [int]$MaxMinutos    = 240,                   # teto de tempo total da execução
  [string]$ClaudeCmd  = 'claude'               # executável do executor (o teste troca por um simulado)
)
```

Por que `TarefasPath` e `EstadoDir` ficam fora do repositório: dentro dele, o `git reset --hard` e o `git clean -fd` do rollback apagariam ou reverteriam o próprio estado do controlador.

### 3.2 Como chamar o executor

- Iniciar `$ClaudeCmd` como **processo externo** (deve funcionar com `.exe` e com `.cmd`), com diretório de trabalho = `$RepoPath`.
- Argumentos obrigatórios: `-p "<prompt>"`, `--output-format json`, `--permission-mode dontAsk`.
- Proibido: `--dangerously-skip-permissions` e `--permission-mode bypassPermissions`.
- Ler o JSON da saída padrão. Campos usados: `is_error`, `result`, `total_cost_usd`.

### 3.3 Ciclo de cada tarefa

1. Escolher a próxima tarefa `pending` cujas dependências (`depends_on`) estejam todas `done`.
2. Registrar o commit base (`git rev-parse HEAD`) e o SHA-256 dos arquivos de `$TestPaths`.
3. Chamar o executor. Timeout = encerramento REAL do processo **e de todos os filhos**; conta como tentativa falhada.
4. O **próprio controlador** roda `$TestCmd` no repositório. Não confiar no relato do executor.
5. Gatilhos críticos (R1), verificados por `git diff`/`git status` contra o commit base:
   - qualquer arquivo de teste alterado, criado ou removido (hash diferente);
   - migrations (caminho contendo `migration`);
   - `package.json`, `package-lock.json`, `requirements.txt`, `pyproject.toml`;
   - exclusão de arquivo que existia no commit base.
   - Se algum ocorrer: status `hold`, **sem commit**, sem rollback (preservar evidência), notificar e **encerrar a execução**.
6. Teste passou e nenhum gatilho: commit com mensagem `tarefa <id>: <titulo>`, status `done`.
7. Teste falhou: `git reset --hard <base>` + `git clean -fd`, SOMENTE dentro de `$RepoPath`; nova tentativa. Ao atingir `$MaxTentativas`: status `failed`. Tarefas que dependem dela permanecem `pending`. As tarefas independentes continuam.
8. Após cada chamada, somar `total_cost_usd`. Se o acumulado passar de `$MaxCustoUsd`, ou o tempo total passar de `$MaxMinutos`: concluir a tarefa atual pelo fluxo normal (passos 4–7), notificar e **pausar** (encerrar sem iniciar outra chamada).

### 3.4 Arquivos em `$EstadoDir`

| Arquivo | Formato |
|---|---|
| `estado.json` | Objeto com, no mínimo: `tarefa_atual` (string ou null), `tentativa` (int), `custo_acumulado_usd` (número), `inicio` (ISO 8601), `atualizado_em` (ISO 8601), `status_execucao` (`rodando` \| `concluido` \| `hold` \| `pausado` \| `falhou`). Regravado a cada etapa (heartbeat). |
| `log.jsonl` | Uma linha JSON por evento, cada uma com `ts` e `evento`. |
| `notificacoes.txt` | Escrito pela função `Notificar()`, isolada. Por ora só grava texto aqui. |

### 3.5 Retomada

Rodar de novo com os mesmos parâmetros retoma de onde parou: tarefas `done` são puladas; tarefa `in_progress` volta ao commit base registrado e recomeça, mantendo a contagem de tentativas.

### 3.6 Códigos de saída

| Código | Situação |
|---|---|
| 0 | Todas as tarefas `done` |
| 1 | Terminou com ao menos uma tarefa `failed` (sem hold nem pausa) |
| 2 | Encerrou por `hold` |
| 3 | Pausou por teto de custo ou de tempo |

## 1. Modo headless
- `claude -p "<prompt>"` roda sem interface. Sai com código 0 no sucesso e diferente de zero na falha; falhas dentro da execução aparecem como resultado na saída padrão. — [headless](https://code.claude.com/docs/en/headless.md)
- `--output-format json` devolve JSON com `result`, `session_id` e metadados, incluindo `total_cost_usd`. O custo é **estimativa do lado do cliente** e pode diferir da cobrança real. — [headless](https://code.claude.com/docs/en/headless.md)
- Encerrado por SIGTERM, sai com código 143 e encerra a árvore de processos dos comandos Bash em andamento. — [headless](https://code.claude.com/docs/en/headless.md)
- `--bare` pula hooks, skills, CLAUDE.md, plugins e `.mcp.json` do projeto, mas **não usa o login da assinatura**: exige `ANTHROPIC_API_KEY`. — [headless](https://code.claude.com/docs/en/headless.md)
- `--permission-prompts none` (v2.1.259+) avisa o Claude de que ninguém pode aprovar e para ele não insistir. — [headless](https://code.claude.com/docs/en/headless.md)

## 2. Modos de permissão
- Modos: `default` (Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- **`dontAsk`**: nega automaticamente tudo o que pediria aprovação. Roda só leituras na pasta de trabalho, comandos somente-leitura embutidos e o que estiver em `permissions.allow` ou `--allowedTools`. Não aparece no ciclo Shift+Tab; usa-se `--permission-mode dontAsk`. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- O modo inicial de `claude -p` pode ser `default` ou `auto`, conforme versão e conta. **Por isso o kit deve passar o modo explicitamente.** — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- `defaultMode` no `.claude/settings.json` do projeto vale para todos os modos, exceto `auto` e `bypassPermissions`. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- `--dangerously-skip-permissions` equivale a `bypassPermissions`; indicado só em container ou VM isolados. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- Escrita em caminhos protegidos (`.git`, `.claude`, `.vscode` etc.) é **negada** em `dontAsk`. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)

## 3. Ponto crítico: confiança da pasta em `claude -p`
- Regras `permissions.allow` do `.claude/settings.json` do projeto **não são aplicadas** em `claude -p` numa pasta nunca confiada; o Claude Code avisa no stderr. Regras `deny` e `ask` continuam valendo. — [permissions](https://code.claude.com/docs/en/permissions.md)
- Hooks do `.claude/settings.json` do projeto **rodam** em `claude -p` mesmo sem confiança. — [headless](https://code.claude.com/docs/en/headless.md)
- Saídas possíveis: passar as regras por `--settings <arquivo>` ou `--allowedTools`; ou marcar a pasta como confiada em `~/.claude.json` (`projects["<raiz>"].hasTrustDialogAccepted = true`). — [permissions](https://code.claude.com/docs/en/permissions.md)

## 4. Sintaxe das regras
- Formato `Ferramenta(especificador)`. Precedência: **deny → ask → allow**; a primeira que casa decide. — [permissions](https://code.claude.com/docs/en/permissions.md)
- Bash: `Bash(npm run *)`; o espaço antes do `*` importa (`Bash(ls *)` não casa `lsof`). — [permissions](https://code.claude.com/docs/en/permissions.md)
- PowerShell: mesma forma, `PowerShell(Get-ChildItem *)`; aliases são normalizados e a comparação ignora maiúsculas. — [permissions](https://code.claude.com/docs/en/permissions.md)
- Arquivos: `Edit(caminho)` e `Read(caminho)` no padrão gitignore. `/caminho` é relativo à origem do arquivo de settings; `//caminho` é absoluto. No Windows, caminhos viram forma POSIX (`C:\Users` → `/c/Users`). Regras `Write(...)` não são consultadas: use `Edit(...)`. — [permissions](https://code.claude.com/docs/en/permissions.md)
- **Regras de Bash/PowerShell não são barreira de segurança**: `Bash(rm *)` não pega `/bin/rm` nem `bash -c 'rm …'`. A proteção real é a verificação externa do controlador. — [permissions](https://code.claude.com/docs/en/permissions.md)

## 5. Windows
- Ferramenta PowerShell: ativada automaticamente sem Git Bash; com Git Bash, ligada por padrão em contas claude.ai e Console (`CLAUDE_CODE_USE_POWERSHELL_TOOL=0` desliga). — [tools-reference](https://code.claude.com/docs/en/tools-reference.md)
- **Sandbox não é suportado no Windows nativo** (só macOS, Linux e WSL2). — [tools-reference](https://code.claude.com/docs/en/tools-reference.md), [permission-modes](https://code.claude.com/docs/en/permission-modes.md)
- `Remove-Item` em caminhos de sistema ou com curinga final é negado em qualquer modo. — [permission-modes](https://code.claude.com/docs/en/permission-modes.md)

## 6. Consequência para o controlador (não é regra do Claude Code, é conclusão)
- Encerrar o executor por timeout exige matar a **árvore** de processos (por exemplo `Process.Kill($true)` no .NET, ou `taskkill /T /F /PID`), porque no Windows o `claude` pode ser um `.cmd` (instalação via npm) que inicia outros processos, e o próprio executor inicia comandos filhos.

function Processo-Vivo([string]$arquivoPid) {
  if (-not (Test-Path $arquivoPid)) { return $false }
  $p = [int](Get-Content $arquivoPid -Raw)
  return [bool](Get-Process -Id $p -ErrorAction SilentlyContinue)
}

function Matar([string]$arquivoPid) {
  if (Test-Path $arquivoPid) {
    $p = [int](Get-Content $arquivoPid -Raw)
    Stop-Process -Id $p -Force -ErrorAction SilentlyContinue
  }
}

function Args-Validos([string]$mockDir) {
  $arquivos = Get-ChildItem $mockDir -Filter 'args-*.json' -ErrorAction SilentlyContinue
  if (-not $arquivos) { return $false }
  foreach ($a in $arquivos) {
    $lista = @((Get-Content $a.FullName -Raw | ConvertFrom-Json).args)
    $txt = ($lista -join ' ')
    if ($txt -match 'dangerously-skip-permissions|bypassPermissions') { return $false }
    if (-not (($lista -contains '-p') -or ($lista -contains '--print'))) { return $false }
    $iOut = [array]::IndexOf($lista, '--output-format')
    if (-not (($iOut -ge 0 -and $lista[$iOut + 1] -eq 'json') -or ($lista -contains '--output-format=json'))) { return $false }
    $iPm = [array]::IndexOf($lista, '--permission-mode')
    if (-not (($iPm -ge 0 -and $lista[$iPm + 1] -eq 'dontAsk') -or ($lista -contains '--permission-mode=dontAsk'))) { return $false }
  }
  if (Get-ChildItem $mockDir -Filter 'cwd-errado-*.txt' -ErrorAction SilentlyContinue) { return $false }
  return $true
}

function Chamadas([string]$mockDir) {

function Rodar-Cenario([string]$nome, [hashtable]$cfg) {
  $base = Join-Path $SaidaDir "work/$nome"
  if (Test-Path $base) { Remove-Item -Recurse -Force $base }
  New-Item -ItemType Directory -Force -Path $base | Out-Null
  $repo = Novo-Repo $base
  $estadoDir = Join-Path $base 'estado'; New-Item -ItemType Directory -Force -Path $estadoDir | Out-Null
  $mockDir   = Join-Path $base 'mock'
  $tarefasPath = Join-Path $base 'TAREFAS.json'
  $sentinela = Join-Path $base 'sentinela-fora-do-repo.txt'
  Set-Content $sentinela 'este arquivo fica fora do repo e não pode ser apagado'
  @{ tarefas = $cfg.Tarefas } | ConvertTo-Json -Depth 5 | Set-Content $tarefasPath
  $baseCommit = (GitR $repo rev-parse HEAD)

  $env:MOCK_CENARIO = $cfg.Mock
  $env:MOCK_DIR = $mockDir

  $psi = [System.Diagnostics.ProcessStartInfo]::new($PwshExe)
  foreach ($a in @('-NoProfile', '-File', $Controlador,
      '-RepoPath', $repo, '-TarefasPath', $tarefasPath, '-EstadoDir', $estadoDir,
      '-TestCmd', $TestCmd, '-TestPaths', 'testes/*',
      '-TimeoutSec', "$($cfg.TimeoutSec)", '-MaxTentativas', "$($cfg.MaxTentativas)",
      '-MaxCustoUsd', "$($cfg.MaxCustoUsd)", '-MaxMinutos', '30', '-ClaudeCmd', $ClaudeCmd)) {
    $psi.ArgumentList.Add($a)
  }
  $psi.WorkingDirectory = $base
  $psi.RedirectStandardOutput = $true; $psi.RedirectStandardError = $true; $psi.UseShellExecute = $false
  $sw = [System.Diagnostics.Stopwatch]::StartNew()
  $proc = [System.Diagnostics.Process]::Start($psi)
  $outTask = $proc.StandardOutput.ReadToEndAsync(); $errTask = $proc.StandardError.ReadToEndAsync()
  $terminou = $proc.WaitForExit($LimiteHarnessSec * 1000)
  if (-not $terminou) { $proc.Kill($true); $proc.WaitForExit(10000) | Out-Null }
  $sw.Stop()
  # Um processo órfão (filho não encerrado) pode manter os pipes abertos: não esperar por eles indefinidamente.
  $semSaida = '<saída indisponível: pipe mantido aberto por processo órfão>'
  $outTask.Wait(5000) | Out-Null; $errTask.Wait(5000) | Out-Null
  Set-Content (Join-Path $base 'controlador-stdout.txt') $(if ($outTask.IsCompleted) { $outTask.Result } else { $semSaida })
  Set-Content (Join-Path $base 'controlador-stderr.txt') $(if ($errTask.IsCompleted) { $errTask.Result } else { $semSaida })
  $exit = if ($terminou) { $proc.ExitCode } else { 'estourou-limite-do-harness' }
  Start-Sleep -Seconds 2

  $ctx = @{ Repo = $repo; Base = $baseCommit; Estado = $estadoDir; Mock = $mockDir; Tarefas = $tarefasPath
            Sentinela = $sentinela; Exit = $exit; Segundos = [math]::Round($sw.Elapsed.TotalSeconds, 1) }
  $verificacoes = [ordered]@{}
  foreach ($k in $cfg.Checks.Keys) {
    try { $verificacoes[$k] = [bool](& $cfg.Checks[$k] $ctx) } catch { $verificacoes[$k] = $false }
  }
  Matar (Join-Path $mockDir 'pid-filho.txt'); Matar (Join-Path $mockDir 'pid-mock.txt')
  $passou = -not ($verificacoes.Values -contains $false)
  [ordered]@{ cenario = $nome; passou = $passou; pontos = $(if ($passou) { 8 } else { 0 })
    exit_code = $exit; segundos = $ctx.Segundos; chamadas_ao_executor = (Chamadas $mockDir)
    verificacoes = $verificacoes }
}

          Get-ChildItem kits -Directory | ForEach-Object {
            pwsh -NoProfile -File testes/run-cenarios.ps1 -KitDir $_.FullName -SaidaDir "saida/$($_.Name)"
          }
